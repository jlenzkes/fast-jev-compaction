# fast-jev-compaction Claude Code mod

This plugin uses Claude Code function hooks to replace a compaction with the
original messages, minus the tool calls and tool results Jev judged no longer
needed. `hooks/fast-jev.ts` is a thin adapter: it reads the plugin options,
finds the TypeSafe key, hands `session.compact` transcripts to the
`fast-jev-compaction` library in `src/` (the plugin folder is the repository
root, so the hook imports it directly) and maps the result back onto session
messages. User and assistant text is never touched. Jev is sent the whole
conversation as `state` (tool outputs replaced by a one-line note) and, for
every tool call outside the pinned first and newest messages, two questions:
whether the call should stay and whether its full output should stay. An
item is kept when Jev's probability reaches `keepThreshold`; a dropped result
is truncated to its first `truncateHeadChars` characters plus a one-line note,
and a dropped call becomes a stub - its tool name, with input and result cut
the same way - unless `dropCalls` is on, when it disappears with its result. A
call an earlier compaction already stubbed is deleted, so a stub lasts one
compaction.

The state is fitted into `maxStateTokens` in stages: tool inputs are
truncated, then long texts are abridged (oldest first, pinned messages last),
then old messages collapse to a `[… N chars omitted …]` note, then old tool
calls shrink to one line each, then old call-less messages are left out and
runs of old call-only messages fold together. If it still does not fit, the
calls are asked in contiguous windows, halved until each window's state fits;
a call whose window cannot fit alone is not asked and stays, and when the goal
and pinned messages alone do not fit, no call is asked and every call stays. Questions are split into as many requests as
needed so each request (state plus questions) stays under `maxRequestTokens`;
the full state is resent with every request. Token counts are estimated
without a tokenizer, calibrated to land a little above what Jev reports.

The mod is an early-access Claude Code function-hook module. The checked-in
type reference was generated by Claude Code **2.1.274**. Enable the function
hooks surface before installing or loading it:

```sh
export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1
export TYPESAFE_API_KEY="<your TypeSafe key>"

claude plugin marketplace add jlenzkes/fast-jev-compaction
claude plugin install fast-jev-compaction@fast-jev-compaction
```

For local development:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir .
```

## Configuration

The plugin declares these `userConfig` values in
`.claude-plugin/plugin.json`:

| Option | Default |
| --- | ---: |
| `keepThreshold` | `0.5` |
| `preserveRecentMessages` | `6` |
| `compactAtPercent` | `60` |
| `minReductionRatio` | `0.25` |
| `dropCalls` | `false` |
| `maxStateTokens` | `25000` |
| `maxRequestTokens` | `30000` |
| `truncateHeadChars` | `300` |
| `model` | `jev-latest` |
| `receipt` | `true` |

The TypeSafe key can be supplied as the sensitive `apiKey` plugin option or
through `TYPESAFE_API_KEY`. The environment variable is the recommended
development setup.

Every option except `apiKey`, `compactAtPercent`, `minReductionRatio`,
`model` and `receipt` is passed straight to the library; see the root README for what they
do. The `session.compact` hook runs at most 8 Jev requests at once and retries
one that fails with a 429 or 5xx once, immediately. If Jev still fails,
the response is malformed, the key is unavailable, or the estimated reduction is below
`minReductionRatio`, the hook logs a fallback and delegates to Claude Code's
built-in compaction. The outcome is shown as a toast and logged with the
reduction, per-reason counts, state size and request count; a per-call
`decisions:` line with both probabilities is logged for diagnosis. The
`turn.complete` hook requests
compaction when `context.percent` reaches `compactAtPercent`, with an
in-flight guard. A host that runs Claude Code as an SDK session (VS Code, the
desktop app, `claude -p`) refuses that request; there the hook toasts
`context at N%: type /compact at a natural stopping point` once when context
crosses `compactAtPercent`, and again each further 10 points, instead of
logging a refusal on every turn. A compaction, or context falling back below
the threshold, starts the count again.

Claude Code stores some messages beside another message rather than as one:
a prompt typed or delivered while a turn runs (a `queued_command`
attachment), a subagent's report that starts a turn of its own, a Stop
hook's feedback. `session.compact` never lists them, and they survive only
when the message they sit beside goes back with its handle, which only a
plain user message does. The `prompt.submit` hook notes every prompt it sees
that is not the user's own at an idle prompt (every prompt with a `turnId`,
whether or not it asked to wait), with the origin `next` accepted (absent
means the user's own) and where the history stood. `hooks/deliveries.ts`
then decides each one at the next compaction: present when the list holds the
plugin's own put-back text or the delivery's own words before the next tool
result past its point; otherwise put back as a plain user message after the
message that was newest when it arrived (idle), or, mid-turn, after the tool
result it came in with: the host hands a queued prompt to `prompt.submit`
after that result is stored (measured with the debug log below in a headless
session on 14 Nov 2026). A mid-turn prompt whose turn ended before any tool
result goes at the end of that turn. Nothing is placed between a tool call
and its result. Where the
point is gone or the place is a guess, the receipt says "placed by
estimate"; a second copy is preferred to a loss. Each put-back opens with a
line the plugin writes, carrying a mark random per compaction and naming the
sender from the accepted origin, and indents every delivered line. The record
is kept per session id in `$.store` (at most 100 deliveries and 512 KiB per
session, 6 sessions), and an entry leaves it only when a later listing shows
its put-back text, it is seen as its own message, or a built-in summary was
handed it; a `precompute` changes nothing. When the plugin path fails, the
built-in summary is handed the history with the deliveries put back. The
library never sees a put-back or a receipt: it compacts the listed messages,
less the plugin's earlier receipts, and the put-backs are inserted after, so
Jev's state, the pinned messages and the fallback decision are as without
them. Unless the `goal` option is set, Jev's goal is the user's last three
prompts, leaving out put-backs from anyone else, host notices (task
notifications, command echoes, peer messages) and receipts. The toast counts what the plugin can see: `kept N/M listed messages
(R rebuilt and D deleted, without what the host stores beside them; P
delivered prompt(s) put back), no summary (X% smaller as returned; ...)`.
With `receipt` on, the main conversation's handed-back history ends with a
receipt (at most 20 lines and 4000 characters) saying the same and naming
the transcript file when the usual path for it exists; a subagent's
compaction gets none.

For maintainers: set the environment variable `FAST_JEV_DEBUG_LOG` to a file
path and each `prompt.submit` and `session.compact` dispatch appends one JSON
line to it (origins, `turnId`, `wait`, text length and hash, never the text,
the listed history's length and newest message, the trigger). It is off
unless set.

## Scope and caveat

Function hooks are early access and may change between Claude Code releases.
This mod uses the generated declarations from 2.1.274 in
`types/claude-code.d.ts`; regenerate and review that file after a
Claude Code upgrade.
